1. **`record_dispatch` is reached from two verbs** — `cli.py:1490` (dispatch) and `cli.py:1636` (resume). Fixing it here covers both; do not fix it at a call site.

- [ ] **Step 3: Resolve the base against the instants directory**

Add a module-level helper in `harvest.py` and call it from `record_dispatch` in place of the bare join. Keep `base` itself untouched — `lint` reads that field, and changing it trades this violation for `unregistered-base`.

```python
def _register_path_for(rec) -> str:
    """The base instant's register, resolved to an ABSOLUTE path at registration time (`I-18`).

    `rec.base_instant` is a bare 8-digit id, so joining it with the register name produced a path
    relative to nothing — unreadable from the tick, and silently so: the source simply reported
    nothing, which is indistinguishable from a register with nothing to say. The instants directory is
    not a field on this object, but `child_instant` is absolute, and the base's folder is its sibling.

    `ROOT_BASE` is synthetic and resolves to no folder; it falls through to the bare join, which is what
    `unharvestable()` already exempts (`A5f`).
    """
    base = str(rec.base_instant).strip()
    if base == ROOT_BASE or "/" in base:
        return str(Path(base) / REGISTER_NAME)
    instants = Path(rec.child_instant).parent
    matches = sorted(p for p in instants.glob("*") if p.is_dir() and _curr_of(p.name) == base)
    if len(matches) > 1:
        raise AmbiguousId(
            f"base {base!r} names {len(matches)} instant folders in {instants} "
            f"({', '.join(p.name for p in matches)}), so the register to watch is ambiguous. An instant "
            f"may hold only one state (OBS-14); resolve the duplicate before dispatching.")
    if not matches:
        return str(Path(base) / REGISTER_NAME)
    return str(matches[0] / REGISTER_NAME)
```

`_curr_of(name)` parses a folder name with `InstantName.parse` and returns its `curr`, returning `None` for anything that does not parse — a directory that is not an instant must not crash a dispatch. Import `AmbiguousId` from `fleet.errors` and `ROOT_BASE`/`InstantName` from `fleet.identity`.

### Task 4: `abort` never leaves an unreadable partial state (F4 / I-27)

**Files:**
- Modify: `fleet/src/fleet/cli.py:2563-2660` (`_do_abort`, and its docstring at 2571-2575)
- Test: `fleet/tests/test_cli.py` (`tests/test_cli.py:1761` pins the existing transaction — keep it green)

**Interfaces:**
- Consumes: nothing.
- Produces: nothing. Exit codes are unchanged; a refusal stays `EXIT_REFUSED`.

**⚠️ The obvious fix is wrong and must not be built.** Moving `pool.release` before `sessions.kill` destroys the verb: a dispatched worker's cwd **is** its leased slot, so at that point the worker is live in that cwd, the release is guaranteed to refuse, and **no live worker would ever be abortable again**. This paragraph exists because that fix reviews well.

**The real defect.** The order is reason → `kill` → `release` → `rename`. `pool.release` refuses when a live pid holds the slot as cwd (`OBS-48`) — and by then the session is dead. The board then reads `UNREACHABLE` plus a spurious `UNKNOWN-SESSION` row: session gone, folder not renamed, slot not released, milestone not disowned. That reads like corruption, and the tempting response — forcing the release or hand-editing the store — is exactly what the refusal prevented.

**A correction to make while you are here.** The docstring says every fallible step precedes "the irreversible one" and names the *rename*. That is not self-contradictory; the gap is that **`sessions.kill` is also irreversible and the docstring does not count it.** Fix the reasoning, not just the behaviour.

**What to build.** The register's own recovery — *wait for the pid, then re-run* — already works, because `kill` is a no-op on a dead session and the re-run completed every remaining step. Make it reachable without reading a register:

1. a **bounded wait** between `kill` and `release` for the slot's cwd-holding pids to exit, converting the common case into a complete abort;
2. when it still refuses, a refusal that **states the partial state explicitly** — session closed, slot still leased, folder still `-inflight-`, milestone still claimed — and names re-running the identical command as the completion.

**Do not complete the rename on the refusing path.** A folder already renamed `-abort-` makes the documented re-run refuse, removing the one recovery that works today.
